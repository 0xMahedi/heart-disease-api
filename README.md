# Heart Disease Prediction API

This academic project trains a binary machine learning classifier using the Kaggle Heart
Disease Dataset and exposes predictions through a FastAPI REST API. It includes Docker,
Docker Compose, Swagger documentation, automated tests, and a Render deployment
configuration.

The model is intended for demonstration and learning only. It is **not medical advice** and
must not be used for diagnosis or treatment decisions.

## Features

- Logistic regression classification with reproducible training
- Numeric validation and missing-feature imputation during training
- FastAPI REST API with Pydantic request validation
- `/health`, `/info`, and `/predict` endpoints
- Swagger/OpenAPI documentation
- Docker and Docker Compose support
- Render deployment configuration
- Automated API tests using FastAPI `TestClient`

## Installation

Python 3.11 or newer is recommended.

Create and activate a virtual environment:

```bash
python -m venv venv
```

Windows:

```bash
venv\Scripts\activate
```

Linux/macOS:

```bash
source venv/bin/activate
```

Install the dependencies:

```bash
pip install -r requirements.txt
```

## Dataset and Training

The CSV is not bundled with this repository. Download the dataset from:

<https://www.kaggle.com/datasets/johnsmith88/heart-disease-dataset>

Place the downloaded CSV at `data/heart.csv`. Do not fabricate a replacement dataset. The
training script checks the required feature names and `target` column, rejects unexpected
non-numeric values, and allows missing feature values to be imputed by the pipeline.

Train the model from the project root:

```bash
python train.py
```

The script uses a reproducible `random_state=42` split, trains a pipeline containing median
imputation, standardization, and `LogisticRegression`, prints accuracy, precision, recall,
and F1 score, and saves this artifact:

```text
model/heart_model.joblib
```

The artifact contains the fitted pipeline, the exact feature order, the target name, the
model type, and evaluation metrics. The generated model should be included in Git if the
assignment requires a ready-to-run deployment. Review the dataset's license before
publishing the CSV itself.

## Run Locally Without Docker

After training the model, start the API from the project root:

```bash
uvicorn app.main:app --host 0.0.0.0 --port 8000
```

The API is available at `http://localhost:8000`.

## Docker

The Docker image copies the trained model into the container. Run training first and verify
that `model/heart_model.joblib` exists:

```bash
docker-compose build
docker-compose up
```

The API is then available at:

```text
http://localhost:8000
```

The Dockerfile also honors Render's `PORT` environment variable and defaults to port 8000.

## API

### `GET /health`

Returns HTTP 200 only when the application and trained model are ready:

```json
{
  "status": "healthy"
}
```

### `GET /info`

Returns the public model type and the exact feature order used for inference.

### `POST /predict`

Request body:

```json
{
  "age": 52,
  "sex": 1,
  "cp": 0,
  "trestbps": 125,
  "chol": 212,
  "fbs": 0,
  "restecg": 1,
  "thalach": 168,
  "exang": 0,
  "oldpeak": 1.0,
  "slope": 2,
  "ca": 2,
  "thal": 3
}
```

Response body:

```json
{
  "heart_disease": true,
  "probability": 0.82
}
```

Invalid request fields are rejected with a FastAPI/Pydantic HTTP 422 response. If the model
has not been trained or loaded, prediction and readiness endpoints return HTTP 503 with a
clear message rather than a Python stack trace.

## Render Deployment

Before deploying, download the dataset, run `python train.py`, and confirm that
`model/heart_model.joblib` is present. The model artifact is required because the deployed
container does not train at startup.

### Deploy using the Render dashboard

1. Push this project to a GitHub repository, including the generated model artifact if the
   repository is intended to run immediately.
2. In Render, choose **New +** and then **Web Service**.
3. Connect the GitHub repository and select the branch to deploy.
4. Set the runtime to **Docker**. Render will use the repository's `Dockerfile`.
5. Select a plan and create the service. No secret or Kaggle credential is needed.
6. Set the health check path to `/health` if Render does not read it from `render.yaml`.
7. After deployment, open the Render URL and check `/health` and `/docs`.

The container listens on `0.0.0.0` and uses Render's `$PORT` when supplied, falling back to
8000 for local Docker usage.

### Deploy using the Blueprint

The included `render.yaml` defines a Docker web service and `/health` health check. In
Render, use **New +** -> **Blueprint** and select the repository. Review the generated service
before applying it.
